# СТРУКТУРА.md — Архитектура программы dzen_pipeline.py
> Модули, схемы данных, сигнатуры, раскладка папок. КОПИРОВАТЬ имена отсюда, не изобретать.

---

## 1. МОДУЛИ (один файл, блоки по порядку)

| Блок | Функции | Кто работает |
|------|---------|--------------|
| Служебное | `read_text(p)`, `extract_json(text)`, `words(text)`, `log(msg)` | код |
| API | `class LLM(model, system_text, dry_run)` → `ask(task, user, max_tokens)` | API / `DRY` в тесте |
| Шаг 2 | `step_structure(llm, topic)` → dict | ИИ |
| Шаг 3 | `step_tables(llm, topic, st)` → dict; `tables_md(t)` → str | ИИ + код |
| Шаг 4 | `step_write(llm, topic, st, t)` → str (авто-расширение ≤3 раз) | ИИ + код |
| Шаг 5 | `local_checks(article, t, structure_md, st)` → rows; `llm_review(...)`; `verify(...)` → (rows, errors); `verification_md(rows, errors)` | код + ИИ |
| Задание 2 | `step_fix(llm, article, errors, t)` → (analysis, article) | ИИ |
| Задание 3 | `step_titles(llm, topic, article)` → str | ИИ + код (длина) |
| Задание 4 | `step_covers(llm, topic, article)` → str | ИИ |
| Запуск | `run_topic(topic, folder, out_root, model, dry, max_fixes)`, `main()` | код |

## 2. ПОТОК ДАННЫХ
```
4 md-файла → system-промт (кэш)
тема → step_structure → step_tables ──┐
                                       ├→ step_write → [<4000 слов? расширить]
                                       ↓
                        verify = local_checks (код) + llm_review (ИИ)
                                       ↓ ошибки?
                        step_fix → verify  (≤3 цикла)
                                       ↓
                        step_titles → step_covers → папка результата
```

## 3. СХЕМЫ ДАННЫХ (JSON)

**structure:** `{"structure":"А|Б|В|Г","name":"","reason":"","story_type":"вымышленная|из жизни"}`

**tables:**
```
{"characters":[{"name","age","role","trait","speech_marker"}],
 "chronology":[{"time","event","who","effect"}],      // метки цифрами: "2 года назад"; обязательно "сейчас"
 "facts":[{"fact","value","source","level","checked"}]}  // может быть пустым
```

**review (ответ ИИ):**
```
{"facts":[{"fact","source","level","status"}],
 "quotes":[{"quote","who","qualification","source","status"}],
 "checklist":{"tone_shift":false,"romance_ok":true,"medical_ok":true,"level4_sources_used":false},
 "errors":["..."]}
```

**строка верификации (rows):** кортеж `(таблица, пункт, статус, детали)`, статус ∈ `✅ ❌ ⚠️`. Ошибка = любая строка со `❌` + `errors` от ИИ.

**titles (ответ ИИ):** `{"titles":["..."×5],"best":1,"why":""}` — длину считает код.

## 4. ТАБЛИЦЫ ВЕРИФИКАЦИИ → ФУНКЦИИ

| Таблица | Что проверяется | Реализация |
|---------|-----------------|------------|
| 2.1 Персонажи | имена из таблицы есть в тексте; нет «лишних» имён (≥3 раз) | код |
| 2.4 Клише | подстроки из СТИЛЬ.md §4 | код |
| 3.1 Факты | числа с %/тыс/млн есть в таблице 2.3; метки `[ТРЕБУЕТ ИСТОЧНИКА]` | код + ИИ |
| 3.2 Цитаты | каждая цитата эксперта есть в атрибуции | ИИ |
| 3.3 Чеклист | объём, Но/А/И, мораль, монетизация, насилие+телефон, «имена изменены», год | код (+ИИ: тон, романтика, медицина, ур.4) |
| 3.4 Хронология | маркеры «N … назад» сверены с таблицей 2.2 (числа словами → цифры) | код |
| 3.5 Повторы | слова из списка ≤2; 4-словные обороты ≤2 | код |

## 6. CLI
```
--topic "..." | --topics-file файл.txt   тема(ы)
--dir ./files                             где 4 md-файла
--out ./out   --model ...  --max-fixes 3
--dry-run                                 тест без API (заготовки DRY)
--check-only текст.txt                    только локальные проверки
--strict-style                            Но/А/И 25–40% вместо 10–40%
```

## 7. ТИПОВЫЕ ТЕМЫ → СТРУКТУРА (для промта шага 2)
А — измена, скрытая ложь · Б — свекровь/тёща/давление родителей · В — прощение, жизнь «после» · Г — развод, дети, опека. Блоки каждой: Вход → Нарастание → Поворот/Кризис → Финал без морали.
